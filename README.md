# K2-kamp

Установленная адаптация KAMP **2.4.1** для **Creality K2 Plus (F008), прошивка 1.1.7.0, Klipper `09faed31-dirty`**. Рабочий сценарий: **Creality Print 7.3 → локальная сеть → принтер с root**. Установлена 20 октября 2026 года; репозиторий обновлён 21 октября.

Это снимок конкретной проверенной конфигурации. Перед переносом необходимо сопоставить прошивку, исходники и собственные настройки.

## Возможности

- Адаптивная сетка строится по `EXCLUDE_OBJECT_DEFINE`, которые должны находиться перед `START_PRINT`. Минимум — 3×3, поле вокруг модели — 5 мм, случайное смещение выключено. Полная карта default 9×9 сохраняется.
- Фактический сервер Creality начинает подготовку через `PRINT_TEMP_SET → G28 Z`, обходя `CX_ROUGH_G28`. В 2.4.1 одноразовое разрешение запускает здесь единственную оптику в режиме новой калибровки. Вложенные G28 сохраняют штатную семантику; прямой START_PRINT и CX_ROUGH_G28 также поддерживаются.
- Затем выполняются горячая коррекция двух Z и заключительный поиск Z без повторного спуска к нижним датчикам. Горячая опорная высота вычисляется по MCU-счётчикам обоих винтов; параметры публикуются согласованно через журнал механической калибровки.
- Повторная NOZZLE_CLEAR не добавляется. Штатная очистка Creality, CFS, продувка и стартовая линия слайсера сохранены. Адаптивная продувка KAMP не включена.
- Карта, механическая калибровка и идентификатор G-code сохраняются на диск. EEPROM-запись связывается с тем же запуском. Восстановление использует штатные механические и CFS-команды и подставляет сохранённую карту после оптики.
- Проверяются исходники, функции и владельцы обработчиков прошивки. Ошибка подготовки останавливает файл и выключает нагрев; конфликтующая внешняя команда не сбрасывает карту действующей печати.

## Подтверждённый результат

Код рассмотрен Astra перед установкой. После полного выключения/включения подтверждены контрольные суммы, загрузка LAN-входа, готовность KAMP и моторов, отсутствие нагрева и сохранность полной карты.

В задании из Creality Print 7.3.0.6157 по LAN зарегистрированы одна оптика, завершение горячей подготовки и карта **4×4 на области 127,5–222,48 мм**. Перепад измерений — **0,125 мм**. Зафиксированы первый слой, сохранённая карта и согласованная запись поколения EEPROM; пользователь подтвердил печать. Визуальное качество первого слоя и завершение всей детали не подтверждены.

**Реальное восстановление после отключения питания пока не проверено.** Сохранение данных и локальные тесты не заменяют такое испытание с CFS.

## Состав и применение

`payload/` повторяет абсолютные пути устройства. Десять файлов побайтово совпадают с установленным пакетом 2.4.1; пути и SHA-256 приведены в `manifest.json`. `patches/` содержит изменения 2.3→2.4→2.4.1 и прежние патчи. `docs/reviews/` сохраняет заключения Astra, `docs/validation/` — сводки без сырых журналов и реквизитов доступа.

Переход с проверенной 2.4 меняет три файла: `gcode_macro.cfg`, `restore_bed_mesh.py`, `kamp_recovery.py`. В 2.4 также изменены штатные `gcode_move.py` и `virtual_sdcard.py`; их согласованная версия обязательна. Суммы каждого этапа находятся в `docs/validation/revision-*-manifest.json`. Перед заменой сверить исходные суммы и закреплённые исходники прошивки; при расхождении сначала сопоставить изменения вручную.

`printer.cfg` содержит параметры конкретного экземпляра: переносить его целиком на другой принтер не следует. Универсального установщика в репозитории нет. Одобрения Astra привязаны к исходным манифестам и локальным установщикам и не разрешают установку на произвольную прошивку.

Менять файлы на свободном принтере с выключенным нагревом и остывшим соплом, после резервного копирования собственных конфигураций и полной карты. После записи сверить суммы и выполнить **полное ручное выключение/включение**: программный RESTART ранее приводил на этом устройстве к сбою motor_control. Затем проверить ready/error KAMP, готовность моторов и default-карту и провести новую контрольную печать через Creality Print по LAN.

## Ограничения

Восстанавливается только новое задание с сохранённой картой и пригодной штатной EEPROM-записью. Задание, прерванное на 2.3, не имеет нужного снимка; ранние слои без checkpoint также не восстанавливаются. Изменение G-code, конфигурации, прошивки или механической калибровки вызывает отказ.

В обновлении EEPROM есть промежуток между disable и окончательным enable. Отключение в этот промежуток приводит к отказу восстановления; предыдущий checkpoint тоже считается отключённым. Восстановление при любой точке обрыва питания не гарантируется.

`MESH=0` не поддерживается. Для ручной полной калибровки на свободном принтере предусмотрен `KAMP_FULL_BED_CALIBRATE`. Ранние штатные вызовы калибровки отложены до защищённого START_PRINT. Обычная пауза без перезагрузки сохраняет карту сеанса.

## Локальные проверки

Python 3.9 или новее; запуск из корня репозитория:

```sh
python -m pip install -r requirements-dev.txt
python tests/verify_payload.py
python tests/run_all.py
```

Четыре группы запускаются отдельно из-за подмены модулей прошивки: **44** проверки подготовки/сохранения/восстановления, **35** проверок ядра адаптера, **19** сценариев LAN, **5** сбоев транзакции установки — всего **103**. Используйте `run_all.py`, а не общий unittest-discover. Результаты сохраняются в игнорируемый `tests/results/`.

Тесты не подключаются к принтеру. Они исполняют сохранённые методы прошивки и Jinja-шаблоны, подменяя MCU, датчики, EEPROM и физическую кинематику. Тестовая функция установки — точный фрагмент рассмотренного установщика, а не самостоятельный сетевой установщик.
