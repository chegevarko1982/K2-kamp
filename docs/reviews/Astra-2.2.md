# Ревизия Astra: KAMP 2.2

Дата: 15 октября 2026. Результат: **кодовых блокеров для записи рассмотренного изменения не обнаружено; минимальная правка одобрена в согласованном пользователем объёме**.

Проверены актуальные proposed, changes.diff, manifest.json, README.md, validation.json, printer-validation.json, а также work/build_kamp_v22.py, work/test_kamp_v22.py и work/update_kamp_v22.py. Ревью не запускало установщик, G-code, перезапуск, нагрев или движения. Из файлов создан только этот отчёт.

## Изменение

Независимое сравнение подтверждает ровно одно удаление: строка 535 прежнего gcode_macro.cfg, `  NOZZLE_CLEAR`. Размер текста уменьшился на 15 байт; удаление этой одной строки воспроизводит новый файл целиком. Остальные шесть файлов пакета совпадают с контрольными SHA256 версии 2.1.

- Исходный SHA256 gcode_macro.cfg: `378ac11945cd61cffd45d9d1be5df140428758e4764dace6318aaebdf4dd3356`.
- Рассмотренный конечный SHA256: `7a338fad95a1502904a232f422dccd5ab54106424ca3998346a9abd4e99a8a6d`.

Штатная ветка prepare=0 целиком сохранена и содержит одну NOZZLE_CLEAR. При prepare=1 повторной NOZZLE_CLEAR внутри START_PRINT нет. Все остальные команды, включая горячую коррекцию двух Z, окончательное уточнение Z, температурные ожидания, BOX_NOZZLE_CLEAN, CFS и адаптивное измерение, остаются прежними. Новых эвристик, маркеров завершения или температурных допусков не добавлено.

Удаление выполнено по прямому решению пользователя «повторная очистка точно не нужна». Ветка prepare=1 продолжает штатно доверять внешней подготовке Creality. Эта ревизия не представляет данное решение как новое доказательство семантики закрытого обработчика.

## Проверки

Проверены код и результаты 47 регрессионных тестов: failures=0, errors=0. Обновлённый тест обеих prepare-веток проверяет число NOZZLE_CLEAR (1/0) и неизменный порядок оставшейся подготовки. Ревью не перезапускало записывающий validation.json тестовый скрипт.

Read-only preflight сообщает: все семь хешей установленной базы совпали; Klipper ready; печать cancelled, SD неактивен, сеанс KAMP неактивен, цели нагревателей нулевые, сопло ниже 50 °C. Штатная Jinja принтера разобрала 73 шаблона изменяемого gcode_macro.cfg. Это проверка синтаксиса, не выполнение нового START_PRINT.

## Установка и активация

Рассмотренный установщик записывает только gcode_macro.cfg. Он проверяет состояние и исходные хеши, сохраняет локальную и удалённую резервные копии, разбирает новый конфиг, записывает и fsync временный файл в том же каталоге, повторяет проверки перед os.replace, затем сверяет конечный хеш и состояние. Команд перезапуска, нагрева или движения в нём нет. Кодовых препятствий для этого способа записи не обнаружено.

После успешной записи файл будет подготовлен к активации, но текущий Klipper продолжит использовать старый загруженный шаблон. С учётом наблюдавшегося сбоя motor_control после soft restart использовать согласованное ручное полное выключение/включение пользователем; установщик RESTART не отправляет. После включения проверить готовность Klipper/KAMP и исходного default, затем пользователь запускает контрольную печать из Creality Print по LAN.

Удалённая процедура в измеренном запуске занимала 81,524 с. Сокращение полного старта версии 2.2 ещё не измерено: температурные интервалы могут перекрываться иначе. На контрольной печати проверить отсутствие повторной NOZZLE_CLEAR, сохранение одной адаптивной сетки и качество первого слоя.
